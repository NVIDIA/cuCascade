# Draft responses to the pinned host cache review

Local drafts for [PR 185's review](https://github.com/NVIDIA/cuCascade/pull/185#pullrequestreview-5740489603). These have not been posted. The [validation record](pinned-host-cache-validation.md) distinguishes completed local evidence from external multi-GPU/application gates. Do not describe the entire review or performance gate as complete while those checks remain open.

1. [Rounded allocation and purge](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468542): Rounded OOM now tries exact-size uncached storage first. Only an exact failure can trigger reclamation, and only if retained capacity covers the full backing request. Recovery rechecks a matching bucket, detaches enough oldest entries atomically, releases outside the mutex, and makes one final exact attempt. The cache belongs to one resource instance shared by its callers. `test_pinned_host_recovery.cpp` covers rounded-to-exact success, insufficient/equal/excess retained capacity, concurrent return, non-OOM failures, padded alignment, and the retry bound. The conservative partial-reclaim trade-off is explicit in the API contract and ADR 0003.

2. [Eviction before metadata reservation](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468555): Incoming entry metadata is staged before any victim is detached. Failed staging preserves retained capacity. Cap accounting is guarded in Release as well as Debug. `test_pinned_cache_insertion.cpp` checks preserved pointer reuse after failed insertion and successful release of every required victim. Oldest-first eviction remains unchanged; replacement policy and node pooling require separate measured justification.

3. [CPU readiness, contents, alignment](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468567): The resource remains stream-ordered. Callers synchronize the allocating stream before host access or use `allocate_sync`; returned contents are uninitialized. Over-aligned requests now receive checked dedicated backing with the original release base retained privately. Invalid alignment and padding overflow fail before acquiring storage. `test_pinned_host_alignment.cpp` exercises those boundaries and failure cleanup. Production pending-DMA tests prove host readiness after synchronization, and `test_pinned_host_production.cpp` verifies actual GPU access through over-aligned mapped memory without hooks.

4. [Zero-size deallocation](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468576): Null and zero-byte deallocation remain no-ops. A live allocation must be returned with its original size and alignment; passing zero for a nonzero allocation violates that caller precondition rather than asking the resource to discover its size. Public documentation states the matching-argument contract. Production zero/null wrapper checks preserve active capture without CUDA work.

5. [Guessed stream device](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468584): Failed stream-device discovery no longer substitutes the current device. Without event tracking, storage can be released only after confirmed stream completion; otherwise it is withheld. `test_pinned_host_device_failures.cpp` checks both successful completion fallback and failed-confirmation withholding, together with an unchanged caller device and clean error state.

6. [Device restoration and cold event creation](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468592): Failure to restore the caller's previous device terminates through the fatal policy. A separately executed helper verifies this outcome without forking an initialized CUDA context. Ordinary discovery, switch, and creation failures use completion confirmation/withholding. Cold event creation occurs outside the cache mutex. `test_pinned_cache_progress.cpp` demonstrates unrelated traffic progresses while a cold create is blocked; successful event creation also verifies device restoration. Real cross-device production checks still require the external host.

7. [Capture and callbacks](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468606): A capturing supplied stream is rejected before allocator CUDA work. Allocation throws; noexcept deallocation withholds storage without recording, waiting, freeing, evicting, or publishing it. Only necessary slab-owner quarantine bookkeeping remains. Unknown capture status follows the conservative policy. `test_pinned_host_capture.cpp` covers large, slab, dedicated, synchronous wrapper, retained-cache, and failed-query behavior while preserving capture validity. CUDA host callback allocator use is unsupported on all relevant paths; ordinary safe reclamation remains supported outside capture.

8. [Recycling suspect events](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468615): Failed completion checks retire the event rather than putting it back into the pool. Live-event accounting is reduced so repeated replacement does not grow the pool indefinitely. The private event retirement cases verify repeated failure/replacement, safe withholding, clean error state, and successful release controls.

9. [Whole-arena quarantine and event destruction](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468629): Slab quarantine is tracked per backing owner, including outstanding slabs. A failed completion retains the affected owner while unrelated backing returns upstream. The shared `cuda_event::reset_no_throw()` relinquishes ownership before attempting destruction, returns status, and clears its own failure; destructor, move assignment, and explicit retirement share it. Lifecycle and slab-quarantine tests exercise empty reset, one destruction attempt, recovery, affected-owner retention, and unrelated-owner release.

10. [Cache-hit contention](https://github.com/NVIDIA/cuCascade/pull/185#discussion_r4445468638): Hit ownership is detached under the mutex, but stream wait submission happens after unlocking; event return and rollback preserve capacity and oldest-first order. Cold event creation also occurs outside the mutex. `test_pinned_cache_progress.cpp` checks unrelated progress during blocked waits/creates and rollback after concurrent refill. The portable paired benchmark includes concurrent hits, full-cap mixed traffic, deterministic eviction, and half-cap rounding, preserving raw hit/miss/eviction counts and variance. Final performance conclusions, regressions, and unavailable application evidence belong in the validation record; node pooling remains outside the approved scope.
